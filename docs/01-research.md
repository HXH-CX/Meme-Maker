# 需求研究（Research）

日期：2026-11-19
状态：已定稿（基于与项目发起人的问答）

## 一句话定位

面向大众的网页版表情包生成器：选模板/传图片/AI 生成底图，加字后一键下载，用于聊天斗图。

## 问答结论

| 问题 | 结论 |
| --- | --- |
| 产品形态 | Web 网页应用 |
| 目标用户 | 大众用户（非设计师），核心诉求是"快、好笑、能直接用" |
| 生成方式 | ① 模板 + 文字 ② 上传图片加字 ③ AI 文生图（三种都做） |
| 风格定位 | 全覆盖：中式斗图风（熊猫头等）+ 可爱贴纸风，模板库分类呈现 |
| 账号体系 | 无需登录，打开即用 |
| AI 服务 | 国内厂商：通义万相（阿里云百炼平台），按量付费 |
| 动图 | 不支持 GIF，仅静态图（PNG/JPG） |
| 编辑器 | 简洁模式：文字内容、上/下位置预设、字号、颜色；不做自由拖拽编辑器 |
| 交付目标 | 先本地开发跑通，暂不考虑公网部署 |

## 用户场景

1. **斗图应急**：聊天中想回一张表情包 → 打开网页 → 搜/选模板 → 输入一句话 → 下载发送。全程目标 < 30 秒。
2. **自有素材加工**：有自己的截图/照片 → 上传 → 加字 → 下载。
3. **创意生成**：想要一张不存在的底图 → 输入描述词 → AI 生成 → 加字 → 下载。

## 关键约束与风险

- **模板版权**：面向大众的产品不能随意抓取网络热门表情包（熊猫头、doge 等多数底图版权不明）。策略：首批模板使用可商用/开源素材或自制底图，模板库结构预留扩充能力。
- **字体版权**：中文字体需选用开源可商用字体（如思源黑体、站酷系列），避免商用字体侵权。
- **AI 成本与延迟**：通义万相按量计费，单张生成约数秒~十几秒。需要：后端代理调用（Key 不落前端）、生成中状态提示、失败重试提示。本地开发阶段 Key 由开发者自备，放在环境变量。
- **AI 内容安全**：文生图需依赖厂商自带的内容审核，前端对明显违规输入不做额外自建审核（本地阶段从简）。
- **无账号**：不做云端作品保存；历史作品可用浏览器 localStorage 暂存（可选增强项）。

## 竞品参考（定性）

- 各类"表情包制作器"小程序/网页：普遍以模板加字为主，体验痛点是模板老旧、广告多、导出带水印。
- 差异化机会：无水印导出、AI 底图生成、干净无广告的简洁体验。

## 范围外（明确不做）

- GIF/动图编辑
- 注册登录、云端作品库、社区分享
- 自由拖拽式高级编辑器（多贴纸、旋转、图层）
- 移动端 App（网页需适配手机浏览器即可）
